# MaxXP — Product Context

## Register

brand — a portfolio where the design IS the product. The visitor's impression ("how was this made?") is the deliverable.

## What it is

maxmohammadi.com: Max Mohammadi's portfolio rendered as a faithful Windows XP desktop ("MaxXP"). A first visit plays the intro film, which logs in and hands off directly to selected work inside a Luna window; shared links and returning visitors open the work directly. Selected work is an XP Filmstrip view: one demo recording loops on the stage, a thumbnail strip picks the next, and build notes live in a Properties sheet. Toolbar views hold working live apps and the complete public GitHub archive. Draggable windows, Start menu, taskbar, all approved demo recordings, resume, contact, and live telemetry remain available.

## Target audience

Technical buyers and hiring managers evaluating Max's work — people who grew up on XP and will judge both the nostalgia fidelity and the engineering craft behind it.

## Brand personality

Nostalgic-authentic, technically show-offy, playful but precise. The joke only lands if the details are right: Luna gradients, Tahoma, balloon tips, Task Manager greens. "Premium" here means *period-correct fidelity + modern smoothness*, never flat-design modernization of XP.

## Anti-references

- Generic "retro Windows" CSS kits that get the gradients wrong and use pixel fonts (that's Win95, not XP).
- Flat/minimal portfolio templates; SaaS landing-page grammar.
- Anything that feels "put together in a short amount of time with no attention to detail" (owner's words) — thin gradients, text glyphs standing in for real UI iconography, static approximations where motion is expected.

## Strategic design principles

1. **Fidelity is the aesthetic.** When in doubt, match what XP actually did (Luna chrome, ClearType-era smoothness, Bliss wallpaper) and then exceed it with modern rendering (real animation, crisp canvas charts).
2. **Alive, not static.** The desktop should feel like a running OS: animated wallpaper, live telemetry, ticking clock, sounds.
3. **Real data only.** Windows display live GitHub/commits.sh data, real videos, real resume — no lorem, no mock stats.
4. **Motion is period-plus.** Crisp sub-200ms transform/opacity motion; no bounce; reduced-motion respected.
5. **Identity-preservation wins.** The Luna look is committed brand; polish within it, never away from it.
6. **Work first, minimal copy.** Show real project imagery before biography or badges. Keep descriptions short, technical detail optional, and a compact live commits.sh summary visible. CRT effects default off; preserve a visitor's saved choice.
7. **Public GitHub only.** Names, descriptions, and repository links must come from anonymous public GitHub responses. Never fetch or bundle private repository metadata. Approved screen recordings remain separate from the repository catalogue. Refresh public data before each build and every six hours; hide unavailable deployments from the Live apps view.
8. **Live apps inside XP.** Deployment links open an interactive Internet Explorer window. Respect sites that prohibit embedding and offer their external link instead.
